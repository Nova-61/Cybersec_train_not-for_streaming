# SIEM Agent

Агент для сбора, парсинга, фильтрации и отправки системных логов батчами по HTTP.

## Функции

- Чтение лог-файлов с отслеживанием изменений через fsnotify (без polling)
- Инкрементальное чтение — помнит позицию в файле, не перечитывает всё заново
- Парсинг форматов Apache/Nginx и Syslog, fallback на определение уровня по ключевым словам
- Фильтрация по минимальному уровню важности
- Отправка батчами с retry при сетевых сбоях
- Graceful shutdown — не теряет накопленный батч при остановке

## Запуск

### Локально

```bash
go mod download
echo '{"log_paths":["test.log"],"server_url":"http://localhost:8080/api/logs","batch_size":10,"batch_interval":5,"retry_count":3,"retry_delay":5,"filter_level":"INFO"}' > config.json
echo "INFO: test log" > test.log
make run
```

### Через Docker Compose (агент + тестовый сервер приёма логов)

```bash
docker compose up -d
docker compose logs -f siem-agent
```

Тестовый сервер принимает логи на `http://localhost:8080/api/logs` и отдаёт последние 10 записей по `GET` на тот же адрес.

## Конфигурация (`config.json`)

| Поле | Описание |
|---|---|
| `log_paths` | Список файлов для отслеживания |
| `server_url` | Куда отправлять батчи |
| `batch_size` | Сколько записей копить перед отправкой |
| `batch_interval` | Через сколько секунд отправлять, даже если батч не заполнен |
| `retry_count` | Сколько раз повторить отправку при ошибке |
| `retry_delay` | Пауза между повторами, сек |
| `filter_level` | Минимальный уровень для отправки (DEBUG/INFO/WARNING/ERROR/CRITICAL) |

Если поле не указано в файле — используется значение по умолчанию, а не 0/пустая строка.

## Известные ограничения

- **Логротейт не обрабатывается.** Если лог-файл пересоздаётся (например, через `logrotate`), агент продолжит следить за старым inode, а не за новым файлом с тем же именем — часть логов может быть пропущена. Требует отдельной доработки reader'а (отслеживание `Create`/`Rename` событий, а не только `Write`).
- **Offset не сохраняется между перезапусками агента.** При рестарте процесса чтение каждого файла начинается заново с начала — возможны дубликаты после каждого перезапуска. Для полного решения offset нужно сохранять на диск (или в отдельное хранилище) и восстанавливать при старте.
- **Нет дедупликации на стороне сервера** — если агент всё же пришлёт дубликаты (например, из-за проблемы выше), сервер примет их как есть.
- Тестовый Flask-сервер — только для локальной проверки, не для продакшена (нет аутентификации, хранит все логи в памяти без ограничения).
